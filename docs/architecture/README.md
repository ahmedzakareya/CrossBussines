# CrossBuy — Architecture Map (as-built)

**Purpose.** An evidence-based map of the CrossBuy system **as it exists in the codebase**, produced before
further platform development. This is discovery documentation, not design documentation.

**Source-of-truth rule.** The codebase is authoritative. Existing `docs/*.md` files were used only as
supporting context and never allowed to override the implementation. Every architectural statement carries a
file path, class, method, DI line, SQL object or view.

## How to read this set

Statements are labelled with one of six categories:

| Label | Meaning |
|---|---|
| **Implemented** | Code exists and is reachable from a route, worker or DI registration |
| **Partial** | Exists for some entities/modules only, or exists but is not wired to a screen/flow |
| **Legacy** | Works, but predates and conflicts with a newer pattern in the same codebase |
| **Planned** | Named in a design document with **no** implementation. Never presented as current |
| **Missing** | Not present at all |
| **Inconsistency** | Two implementations of the same concern that disagree |

## The three findings that shape everything else

1. **Company isolation is a column convention, not a mechanism.** `CompanyID` is present on most business
   tables but there are **no EF global query filters**; every query re-implements the filter, and eight
   controllers hard-code `private const int DefaultCompanyId = 1`. See 08 and 13. *(Unchanged by Stage 0 — this is
   the single highest-leverage change still outstanding.)*
2. **Authorization is thin above authentication.** Of **381 mutating actions, 306 carry no module permission
   attribute**. 193 routed screens are gated by `[SessionValidation]` alone. See 13. *(The earlier phrasing — "of 270
   write actions, 16 carry a module permission" — rested on a body heuristic that measured nothing useful; see
   CORRECTION-001.)*
3. **The Platform Kernel is the only part of the system with uniform transaction, audit and retry
   guarantees** — and it currently covers **9 of 58** registered objects, with a timeline on **4**. See 09 and 07.
   Stage 0 Batch B made the kernel's queue **observable and safely retryable**; it did not widen its coverage.
