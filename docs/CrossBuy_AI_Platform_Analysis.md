# CrossBuy — تحليل وتصميم منصة الذكاء الاصطناعي المتكاملة (AI Platform)

> **الغرض:** تصميم **طبقة ذكاء اصطناعي موحّدة** تغطّي كل وظائف نظام CrossBuy (HR + المحاسبة +
> المخزون + الإدارة)، تُبنى كـ **خدمة بايثون منفصلة (FastAPI)** بجوار الـ .NET، وتحترم كل القيود
> المعمارية القائمة (الشجرة الهرمية، الـ SQL-only، الـ bilingual AR/EN RTL، الـ JWT API + SignalR،
> Flutter).
>
> دي وثيقة **تحليل + تصميم** (Analysis & Design) — مرجع يتقسّم منه prompts مرحلية لـ Claude Code،
> **مش كود نهائي**.
>
> **مبدأ حاكم:** الـ AI **مستشار ومساعد، مش مصدر حقيقة**. المنطق الحسابي والقواعد الصارمة
> (توازن القيد، الصلاحيات، قفل الفترات، خصم رصيد الإجازة) تفضل **في الـ .NET deterministic**.
> الـ AI يقترح ويفسّر ويصنّف ويتنبأ — والاعتماد النهائي دايمًا بشري أو بقاعدة ثابتة.

## 1. الرؤية والمبادئ الحاكمة

الهدف: تحويل CrossBuy من نظام **بيسجّل البيانات** إلى نظام **بيفهمها ويساعد في اتخاذ القرار**.
المستخدم يقدر يكلّم النظام بالعربي العادي، النظام يقترح القيود ويصنّف الفواتير ويكشف الشذوذ
ويتنبأ بالتدفق النقدي ويلخّص التقارير ويجاوب على أسئلة الموظفين — كل ده مع احترام الصلاحيات
والـ workflows الموجودة.

### المبادئ الخمسة (ثابتة)
1. **AI يقترح، الإنسان/القاعدة يعتمد.** أي ناتج AI مالي = **Draft** يمرّ على نفس الـ approval
   workflow الموجود (`LeaveApprovalStep` / `ApprovalStep`).
2. **مصدر الحقيقة هو SQL Server + الـ .NET.** الخدمة البايثونية **stateless** قدر الإمكان،
   بتقرا/تكتب عبر الـ .NET API مش مباشرة على الجداول الحرجة.
3. **كل شيء bilingual.** الـ prompts والردود والتفسيرات AR/EN. Claude قوي جدًا في العربي.
4. **قابلية التتبع (Auditability).** كل اقتراح AI يتسجّل: المُدخل، الموديل، الثقة، وقرار المستخدم.
   ده شرط للمحاسبة وللتحسين المستمر.
5. **التدرّج بالقيمة.** كل قدرة تتبني وتُقاس قبل التوسّع — لكن البنية التحتية موحّدة من الأول.

## 2. لماذا بايثون منفصلة وليس تحويل النظام

> **القرار: لا نحوّل وظائف النظام إلى بايثون. نضيف طبقة بايثون مساعدة.**

- النظام الأساسي (.NET 8 + EF + SQL + Flutter) **سليم ومستقر** ومتشابك مع الصلاحيات والـ SignalR
  والـ Identity. إعادة كتابته بايثون = مخاطرة ضخمة بلا عائد.
- بايثون هي **النظام البيئي الطبيعي للـ AI/ML** (LLM SDKs، scikit-learn، Prophet، Vision، OCR).
  بنستخدمها فيما تتفوّق فيه فقط.
- **الفصل = عزل المخاطر:** لو خدمة الـ AI وقعت، النظام المحاسبي/الـ HR يفضل شغّال 100%.
- **اللغة الموحّدة بينهم = JSON عبر REST** (زي تكامل ETA/IPaymentGateway اللي اتعمل بنفس النمط).

## 3. المعمار العام (Python ↔ .NET)

```
┌─────────────────────────────────────────────────────────────┐
│  Flutter (mobile)            Razor + Metronic (web)          │
│       │ زر "مساعد CrossBuy" / اقتراحات inline                 │
│       ▼                                                       │
│  ASP.NET Core .NET 8  (مصدر الحقيقة + الصلاحيات + الـ workflows)│
│   - يبقى البوابة الوحيدة للـ DB الحرج                          │
│   - AiController.cs  ← proxy موثّق (JWT) للخدمة البايثونية     │
│   - يطبّق الصلاحيات قبل وبعد نداء الـ AI                       │
│       │  REST/JSON  (داخلي: localhost أو شبكة خاصة)            │
│       ▼                                                       │
│  Python AI Service  (FastAPI, port :8000)                    │
│   ├─ /assistant   ← Copilot: لغة طبيعية + tool-calling        │
│   ├─ /classify    ← تصنيف فواتير/معاملات → حساب GL + مركز تكلفة│
│   ├─ /extract     ← OCR/Vision: صورة فاتورة → بنود منظّمة      │
│   ├─ /forecast    ← تنبؤ نقدي/مخزون (ML تقليدي)               │
│   ├─ /anomaly     ← كشف الشذوذ في القيود/المصروفات            │
│   ├─ /summarize   ← تلخيص تقارير بالعربي                       │
│   └─ /rag/query   ← أسئلة على السياسات والأدلة                │
│                                                              │
│   المكوّنات:                                                   │
│   - LLM: Claude API (Opus 4.8 للمهام المعقّدة، Haiku للسريعة)  │
│   - ML: scikit-learn / Prophet / statsmodels                 │
│   - Vision/OCR: Claude Vision أو نموذج OCR مخصّص              │
│   - Vector store: pgvector / SQLite-VSS / Qdrant (محلي)       │
│       │  Tool-calling يرجع للـ .NET لتنفيذ أي فعل             │
│       └──────────────► .NET API (نفس البوابة، نفس الصلاحيات)  │
└─────────────────────────────────────────────────────────────┘
```

**القاعدة الذهبية للتدفق:** الموبايل/الويب → .NET → Python → (إن لزم فعل) → .NET → DB.
الخدمة البايثونية **لا تكتب على الجداول المالية مباشرة**؛ بترجّع اقتراح، والـ .NET ينفّذه
بنفس قواعده وصلاحياته.

## 4. الحزمة التقنية (Tech Stack)

| الطبقة | الاختيار | السبب |
|--------|----------|-------|
| إطار الخدمة | **FastAPI** + Uvicorn | async، توثيق تلقائي (OpenAPI)، مناسب لـ LLM streaming |
| LLM | **Claude API** (`claude-opus-4-8` للمعقّد، `claude-haiku-4-5` للسريع/الرخيص) | الأقوى في العربي + tool-calling ممتاز + رؤية |
| Tool-calling | Anthropic Tools API | يخلّي الـ LLM ينده الـ .NET endpoints كأدوات |
| ML تقليدي | scikit-learn (تصنيف/شذوذ)، **Prophet**/statsmodels (تنبؤ زمني) | كشف الشذوذ والتنبؤ **مش محتاجين LLM** — أرخص وأدق |
| OCR/Vision | Claude Vision (بداية) → نموذج OCR مخصّص لو الحجم كبر | استخراج بيانات الفواتير |
| RAG | embeddings + **Qdrant محلي** (vector store منفصل، مجاني) — ملاحظة: `pgvector` خاص بـ PostgreSQL ولا يصلح لـ SQL Server | أسئلة على السياسات/الأدلة |
| التحقق | **Pydantic** (schemas صارمة لكل ناتج AI) | يمنع الهلوسة في البنية، retry عند الفشل |
| النشر | نفس السيرفر، عملية بايثون منفصلة (systemd/NSSM على ويندوز) | عزل، سهولة restart |

> **ملاحظة Claude:** قبل أي تنفيذ فعلي للـ LLM، راجع مرجع الـ API (الموديلات، التسعير، caching،
> tool-use، token counting) — استخدم سكِل `claude-api`. ولا تجاوب عن أسعار/حدود من الذاكرة.

## 6. المساعد الموحّد (CrossBuy Copilot)

قلب المنصة. واجهة محادثة واحدة (ويب + موبايل) تفهم العربي وتنفّذ عبر **tool-calling**:

```
المستخدم: "اعمل قيد إيجار مكتب 5000 جنيه على فرع القاهرة بتاريخ النهاردة"
   ▼
Claude (مع أدوات مُعرّفة):
   1. tool: search_accounts("إيجار")        → حساب مصروف الإيجار
   2. tool: search_cost_centers("القاهرة")  → CostCenter للفرع
   3. tool: get_cash_accounts()             → الخزينة/البنك
   4. يبني اقتراح قيد متوازن (مدين إيجار / دائن نقدية)
   ▼
.NET: يستلم الاقتراح → يطبّق قواعد الترحيل والصلاحيات → يخزّنه Draft
   ▼
المستخدم: يراجع ويضغط "اعتمد" → يدخل الـ posting engine العادي
```

**التصميم:**
- كل **أداة (tool)** = endpoint موجود فعلًا في الـ .NET API (read أو propose-draft). الـ LLM
  لا يكتب SQL ولا يلمس الـ DB — بس بيختار الأدوات ويملا معاملاتها.
- **الصلاحيات تُطبَّق على مستوى الأداة في الـ .NET**، مش في الـ prompt. لو المستخدم مالوش صلاحية،
  الأداة ترفض بغضّ النظر عن أي شيء قاله للـ LLM (حماية من prompt injection).
- **سياق المستخدم** (هو مين، شركته، فرعه، دوره) يُحقَن في الـ system prompt من الـ JWT، مش من كلامه.
- كل ناتج بنيوي يتحقّق بـ **Pydantic schema** قبل ما يرجع للـ .NET.

## 7. طبقة المعرفة والاسترجاع (RAG)

لإجابة الأسئلة عن السياسات والأدلة والبيانات الوصفية بدقة وبدون هلوسة:

- **المصادر:** دليل المستخدم (`docs/CrossBuy_User_Manual.html`)، سياسات الإجازات/الحضور،
  شجرة الحسابات وأوصافها، قواعد الضرائب، توثيق الوحدات.
- **الـ vector store:** **Qdrant محلي** (خدمة منفصلة، مجانية). جدول `AiKnowledgeChunks` في SQL
  يحتفظ بالنص والميتاداتا؛ الـ embeddings تعيش في Qdrant. (لا نستخدم `pgvector` لأنه PostgreSQL فقط.)
- **الآلية:** تقطيع (chunking) → embeddings → Qdrant → استرجاع أعلى-k → حقنه في الـ prompt
  مع **إلزام الاستشهاد بالمصدر** (citations). لو مفيش مصدر → "لا أعرف" بدل الاختراع.
- **التحديث:** job دوري يعيد فهرسة المستندات المتغيّرة.
- **الخصوصية:** بيانات الموظفين الحساسة لا تدخل الـ vector store العام؛ تُستعلم live عبر API
  مع صلاحيات المستخدم.

## 8. الأمان والحواجز (Guardrails & Human-in-the-loop)

| الخطر | الحاجز |
|-------|--------|
| هلوسة في الأرقام المالية | الـ AI **لا يحسب أرقام نهائية**؛ القيد يُبنى ويُتحقّق في الـ .NET (Σ مدين = Σ دائن). |
| Prompt injection | الصلاحيات والهوية من الـ JWT/الـ .NET، **مش** من نص المستخدم. الأدوات تتحقّق مستقلة. |
| فعل غير مصرّح | كل فعل = Draft يمرّ على الـ approval workflow. مفيش auto-post من الـ AI. |
| تسريب بيانات حساسة لمزوّد الـ LLM | تقليل الـ payload لأقل قدر، إخفاء هوية حيثما أمكن، اتفاقية معالجة بيانات، خيار on-prem لاحقًا. |
| تتبّع | جدول `AiInteractions` يسجّل: المُدخل، الموديل، التكلفة، الثقة، قرار المستخدم (accept/edit/reject). |
| تكلفة منفلتة | حدود استخدام per-user/per-day، caching، توجيه المهام السهلة لموديل أرخص (Haiku). |

## 9. نموذج البيانات الإضافي (جداول الـ AI)

> تُنفّذ بـ `sqlcmd` يدويًا (الـ migrations مكسورة — Trap #1)، PascalCase، أعمدة تدقيق.

```sql
-- سجل كل تفاعل AI (تتبّع + تحسين مستمر)
CREATE TABLE AiInteractions (
    ID            BIGINT IDENTITY PRIMARY KEY,
    CompanyID     INT NOT NULL,
    UserId        NVARCHAR(450) NULL,        -- AspNetUsers.Id
    Feature       NVARCHAR(60)  NOT NULL,    -- Assistant/Classify/Extract/Forecast/Anomaly...
    InputText     NVARCHAR(MAX) NULL,
    OutputJson    NVARCHAR(MAX) NULL,        -- الناتج المنظّم
    Model         NVARCHAR(60)  NULL,        -- claude-opus-4-8 ...
    InputTokens   INT NULL, OutputTokens INT NULL,
    Confidence    DECIMAL(5,4)  NULL,
    UserDecision  NVARCHAR(20)  NULL,        -- Accepted/Edited/Rejected
    CreatedAt     DATETIME2 NOT NULL
);

-- اقتراحات بانتظار مراجعة بشرية (طابور موحّد)
CREATE TABLE AiSuggestions (
    ID            BIGINT IDENTITY PRIMARY KEY,
    CompanyID     INT NOT NULL,
    Feature       NVARCHAR(60) NOT NULL,
    TargetType    NVARCHAR(40) NULL,         -- JournalEntry/PurchaseInvoice/LeaveRequest...
    TargetId      INT NULL,                  -- لو تحوّل لـ Draft فعلي
    PayloadJson   NVARCHAR(MAX) NOT NULL,
    Status        NVARCHAR(20) NOT NULL DEFAULT 'Pending', -- Pending/Applied/Dismissed
    CreatedBy NVARCHAR(450) NULL, CreatedAt DATETIME2 NOT NULL
);

-- فهرس RAG (لو vector store على SQL عبر pgvector/خارجي؛ وإلا في Qdrant)
CREATE TABLE AiKnowledgeChunks (
    ID          BIGINT IDENTITY PRIMARY KEY,
    Source      NVARCHAR(200) NOT NULL,      -- UserManual/Policy/COA...
    Lang        CHAR(2) NOT NULL,            -- ar/en
    Content     NVARCHAR(MAX) NOT NULL,
    -- Embedding: عمود vector أو مرجع خارجي
    UpdatedAt   DATETIME2 NOT NULL
);
```

## 10. واجهة الـ API للخدمة البايثونية (FastAPI)

كلها داخلية، تُنادى من الـ .NET فقط (mTLS أو shared secret على شبكة خاصة):

| Endpoint | الغرض | المُخرج |
|----------|-------|---------|
| `POST /assistant/chat` | محادثة Copilot (streaming) | رسالة + أدوات مطلوبة |
| `POST /classify/invoice` | تصنيف فاتورة → GL + cost center | `{accountId, costCenterId, confidence}` |
| `POST /extract/invoice` | OCR صورة فاتورة | بنود + ضريبة + مورد (Pydantic) |

## 12. التكلفة والأداء

- **توجيه الموديل (Model routing):** المهام السهلة (تصنيف قصير، تلخيص) → Haiku (أرخص/أسرع)؛
  المعقّدة (Copilot متعدّد الخطوات، استخراج) → Opus/Sonnet.
- **Prompt caching:** الـ system prompt وشجرة الحسابات وقواعد الترحيل تتكرر → caching يوفّر كثيرًا.
- **ML تقليدي بدل LLM** للتنبؤ والشذوذ → شبه مجاني وأدق في الأرقام.
- **Batching** للمهام غير التفاعلية (تصنيف دفعة فواتير ليلًا).
- **حدود استخدام** per-user/per-company + مراقبة التكلفة من `AiInteractions`.

> راجع التسعير الفعلي وحدود الـ tokens من مرجع `claude-api` وقت التنفيذ — لا تعتمد على أرقام مخزّنة.

## 13. مسار التنفيذ المرحلي (Phased Roadmap)

> كل Phase = أساس مشترك يُبنى مرة، ثم قدرات فوقه. **لا نبني كل القدرات دفعة واحدة** رغم أن الهدف
> منصة كاملة — نبني البنية التحتية مرة، ونضيف القدرات بالتدريج بقيمة مقاسة.

**Phase 0 — الأساس (البنية التحتية):**
خدمة FastAPI + اتصال Claude API + `AiController` proxy في الـ .NET + جداول `AiInteractions`/
`AiSuggestions` + الصلاحيات + التتبّع + health checks. (لا قدرات للمستخدم بعد — بنية فقط.)

**Phase 1 — أعلى قيمة وأسرع عائد:**
1. المساعد المحاسبي (قيود بالعربي) — 🟢⭐⭐⭐
2. تصنيف فواتير الموردين — 🟢🔵⭐⭐⭐
3. مساعد الموظف بالعربي (إجازات) — 🟢🟠⭐⭐⭐

**Phase 2 — الذكاء التحليلي (ML):**
4. كشف الشذوذ في القيود — 🔵
5. تنبؤ التدفق النقدي + تنبؤ المخزون — 🔵
6. مساعدة التسوية البنكية — 🔵

**Phase 3 — الرؤية والمعرفة:**
7. استخراج الفواتير OCR — 🟣
8. طبقة RAG + البحث الذكي عبر النظام — 🟠

**Phase 4 — المساعد الموحّد الكامل (Copilot):**
9. توحيد كل الأدوات تحت Copilot واحد + مولّد التقارير بالكلام + التلخيصات.

## 13.5 عقد التوسّع: كيف تنمو المنصة مع كل وحدة جديدة

> **المبدأ:** الأساس (Phase 0) يُبنى **مرة واحدة** وهو محايد تجاه الوحدات. أي وظيفة AI جديدة —
> في أي وحدة حالية أو مستقبلية — تُضاف بنفس الخطوات الثلاث الثابتة، **بدون إعادة بناء وبدون لمس
> القدرات القديمة**. التوسّع بالإضافة (additive)، لا بإعادة الكتابة.

**نمط إضافة أي قدرة AI جديدة (ثابت ومتكرر):**
```
وحدة/وظيفة جديدة في النظام
   1) endpoint قراءة (أو propose-draft) في .NET يحترم صلاحيات المستخدم   ← "أداة" جديدة
   2) Pydantic schema للناتج المنظّم في بايثون                          ← تعريف الشكل + منع الهلوسة
   3) تسجيل الأداة في tools الـ Copilot + ربط زر/اقتراح في الواجهة       ← التفعيل
        ▼
   الـ Copilot الموحّد يفهم القدرة الجديدة فورًا (tool-calling) دون تعديل القديم
```

**لماذا ينمو هذا التصميم بثبات:**
1. **أساس محايد:** خدمة بايثون + `AiController` proxy + جداول التتبّع + الأمان = طبقة واحدة تخدم كل
   الوحدات الحالية والمستقبلية (محاسبة/مخزون/HR/أي وحدة جديدة).
2. **الـ Copilot يتوسّع بالإضافة:** قدرة جديدة = أداة جديدة في القائمة؛ النموذج يستخدمها فورًا،
   ولا تُمَس الأدوات القائمة.
3. **تعلّم تراكمي:** `AiInteractions` يجعل التصنيف/الاقتراح يتحسّن مع كل قرار مستخدم (few-shot)
   دون كود جديد.
4. **mapping بالإعداد لا بالكود:** نمط `PostingRules` (صف في جدول، لا تعديل كود) يُعمَّم على كل
   طبقات الـ AI، فالتخصيص لكل عميل/شركة لا يتطلب نشرًا جديدًا.

**الشرط الوحيد:** هذا التوسّع السلس **مشروط ببناء Phase 0 بشكل سليم**. لذلك Phase 0 كله بنية تحتية
بلا قدرات مرئية — وهو **استثمار مقصود** يجعل كل وحدة لاحقة رخيصة الإضافة بدل أن تكون ألمًا متكررًا.

## 14. مصائد ومخاطر خاصة بـ CrossBuy

1. **الـ migrations مكسورة** — كل جداول الـ AI بـ `CREATE TABLE` يدوي عبر `sqlcmd`، وأسماء الأعمدة
   = أسماء الـ properties (EF maps by name).
2. **سيرفر واحد :5000 للـ .NET** — خدمة بايثون على بورت منفصل (`:8000`)؛ خلي السيرفرين منفصلين
   لكن متناغمين، والـ SignalR يفضل في الـ .NET instance الواحد.
3. **العربي عبر console يبان `?????`** — تحقّق من النواتج العربية عبر JSON/التطبيق مش raw console.
4. **أيقونات Metronic** — `ki-translate`/`ki-globe` مش موجودين؛ استخدم inline SVG لأي أيقونة AI جديدة.
5. **لا تتجاوز الصلاحيات** — الـ AI لازم يرى فقط ما يراه المستخدم؛ طبّق الصلاحيات في الـ .NET tools.
6. **الأرقام المالية** — لا تترك الـ LLM يحسب مجاميع نهائية؛ التحقّق الحسابي في الـ .NET دايمًا.
7. **الخصوصية القانونية** — بيانات الموظفين/الرواتب حساسة؛ قلّل ما يُرسل للـ LLM واتفق على معالجة البيانات.
