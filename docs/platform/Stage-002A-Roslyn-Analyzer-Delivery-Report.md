The first attempt reported **709 passed / 72 skipped**, because `CROSSBUY_TEST_SQL` was not set in this session's

**781 / 781 / 0 skipped**. Both runs are reported; the 781 is the one that counts, and the 709 is recorded because a
count that depends on an unset environment variable is exactly the kind of thing that later reads as a regression.

## 4. What the analyzer found that the scanner could not

Not just parity — three substantive new facts.

**1. 124 of the 143 debt endpoints are authenticated, not unguarded.** CBA002 separates "this request has a verified
identity and a CSRF token but nobody decides what it may change" from "this endpoint has nothing at all". The first
category is 124 endpoints; the second is 19. That changes how Wave 2 should be sequenced and was not previously
measurable.

**2. A false positive in the analyzer's own first heuristic, found by dogfooding.** The initial run flagged
`PermissionTarget.ForSubjectEmployee` — a DTO factory — as an unrecognised guard, because the heuristic matched the
containing *type* name. Narrowed to method names, with `CanAsync`/`RolesAsync` added so an undeclared ninth access
service is still caught. Both directions pinned by tests. Reported rather than quietly corrected, because the value
of dogfooding is the finding.

**3. Two anonymous mutating endpoints verified by reading, not by trusting the classification.**
`HyperPosController.Login` and `PosAppController.Login` are `[AllowAnonymous]` POSTs credited in-body. Confirmed
correct: both sign in, then refuse when `ResolveByUserIdAsync` returns null, then apply a lane whitelist and a
cross-company guard. A credit on a login endpoint is exactly where a false credit would hide, so it was checked.

## 5. Judgement calls, stated

**`DevOnly` is recognised but not credited.** The brief lists it under approved authorization paths; §4 forbids
crediting anything that checks no role, and §10 requires 143 to match exactly. Crediting an environment gate would
violate both. It is recognised as its own declared category and named in CBA002's message. Zero count impact.

**Warning by default, Error by configuration.** The brief asks for both "Warning only" and "new debt → build Error".
Descriptors ship at Warning; the escalation is an `.editorconfig` decision, and a test proves it works by overriding
CBA001 to Error and asserting the reported severity. The `.editorconfig` is written out in the design document and
**not applied**.

**The call graph stops at the controller boundary.** It does not descend into arbitrary application services to
discover that one happens to check something — that would credit a domain rule nobody declared as a control, which
is CORRECTION-004's shape. Consequence stated plainly: **some of the 143 may not be true gaps.** The remedy is to
promote such a service into the declared surface deliberately, so the count moves for a reviewable reason. Open item.

**The baseline says "CBA007" where the brief says CBA004.** CBA004 was implemented per the brief. The baseline file
was **not edited** — it is frozen and shrink-only, and rewriting its prose is an owner decision. One line of prose;
the file's data reconciles perfectly. Owner decision needed.
