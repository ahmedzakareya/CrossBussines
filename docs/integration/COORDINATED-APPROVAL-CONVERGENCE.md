## Integrity and confidentiality

Inventory's delegated document, approval decision and event share an ambient ScopedTx. A new SQLite behavioral test forces failure after a transactional delegate persisted its document; a fresh context observes no document, a Pending decision and no Approved event. Retrying yields one document and one Approved event. The SQL Server transaction suite is included but is not executed under this wave's no-SQL restriction.

HR intermediate Advanced and terminal Approved remain separate; level-zero auto-approval creates no fictitious approver task. Employee and Leave payloads retain the source's restricted contract and authoritative company envelope. A rejected request has no reopening transition. Reapplying creates a new request row and therefore a distinct ID and dedup key; new behavioral tests cover this explicitly. The phrase “cycle-keyed” does not imply a separate stored cycle number.

The Inventory approval task has no assigned employee. Activating its rule without the source read layer would expose work to generic task viewers or make it unreachable by eligible managers. Its provider now delegates to InventoryApprovalService.ApprovalInboxAsync. The real authority enforces company, manager role, Pending state and separation of duties. The deferred dependencies avoid the module/provider construction cycle; Stage1DiWiringTests validates the actual approval services, authorities and recorder in a scoped graph.

TaskService list, count, KPI summary and detail reads, and existing TaskReportService aggregates, use the shared authorizer. Source admission grants read only, not edit or reassignment. The production TaskService factory requires the authorizer together with the HOLD dependencies. Historical hand-built constructors remain compatible; they are not the production registration. AutoGeneratedAsync uses an inner join to authorized tasks, so excluded tasks cannot leak their IDs through unmatched ledger rows.
