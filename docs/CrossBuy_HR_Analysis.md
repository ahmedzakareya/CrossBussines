## 0) ملخص تنفيذي — تصحيح الصورة

الفحص كشف أن الـ HR **أنضج مما افترض الـ backlog**، مع فجوتين حقيقيتين واضحتين:

| المجال | الحالة الفعلية |
|---|---|
| ملف الموظف + الهيكل التنظيمي (Hierarchicals) + المسميات | ✔ مبني |
| الإجازات (طلب + سلسلة موافقات هرمية + رصيد محسوب) | ✔ مبني (متقدّم) |
| **الرواتب: محرك الحساب + جسر المحاسبة (قيد شهري)** | ✔ **مبني وشغّال ومُختبَر** (تصحيح: الـ backlog ظنّه غير مؤكَّد) |
| **جدول الإجازات الرسمية (Official Holidays)** | ✘ **ناقص تمامًا** 🔴 |
| **التقاط الحضور والانصراف (Attendance capture)** | ✘ **ناقص تمامًا** 🔴 (موجود فقط *سياسات* بلا سجلات) |
| قسائم الراتب (Payslips AR/EN) | ✘ ناقص 🟠 |
| صرف الرواتب (Disbursement) + تصفية 2103 | ✘ ناقص 🟠 |
| توريد الاستقطاعات للجهات (ضرائب/تأمينات) | ✘ ناقص 🟠 |
| عقود الموظف + تنبيهات انتهائها + خزنة مستندات | ✘ ناقص 🟠 |
| بدل الإجازة النقدي (Encashment) + مخصص الإجازات محاسبيًا | ✘ ناقص 🟡 |
| الإضافي/التأخير/الغياب في الراتب | ◐ الحقول معرّفة في `SalaryPolicies` لكن **لا تُحتسَب** (تنتظر الحضور) |

**الخلاصة:** الحلقة HR↔المحاسبة **مقفولة بالفعل** على مستوى القيد الشهري. الفجوة الحقيقية
هي **طبقة الزمن (الحضور + الإجازات الرسمية)** التي تغذّي الراتب بالخصومات/الإضافي، ثم
**مخرجات الموظف** (قسائم/صرف) و**التوريد الحكومي**.

## 1) المبني فعلًا (بالأدلة)

### 1.1 شؤون الموظفين والهيكل ✔
- `Models/Context/Admin/Employee.cs` — ملف كامل: بيانات شخصية (اسم/ميلاد/جنس/حالة/صورة)،
  وظيفية (`JobTitleID`, `BranchID`, `EmpCompanyID`, `DepartmentID`, `EmploymentType`)، `DateOfJoining`, `IsActive`, `UserId`.
- `EmployeeService` — CRUD + رفع صورة (`/uploads/employees/`) + ربط السياسات.
- الهيكل التنظيمي `Hierarchical` (شجرة ذاتية المرجعية: شركة→فرع→إدارة→موظف، أنواع عبر `HierarchicalType`)
  + `AdministrativeStructureService`. **هو نفسه** أساس الفروع ومراكز التكلفة (تكامل مع المحاسبة/المخزون).
- المسميات `JobTitle` (AR/EN) + `IJobTitles`. شاشات: PeopleController (Profile/Structure)، AdminController (EmployeesList/EmployeeData).

### 1.2 الإجازات ✔ (متقدّم)
- كيانات: `LeaveRequest`, `LeaveApprovalStep` (متعدد المستويات), `LeaveTypes`, `LeavePolicies`
  (`EntitlementDaysPerYear`, `CarryOverLimit`, `NoticePeriodDays`, `RequiresMedicalCertificate`).
- `LeaveWorkflowService`: يبني سلسلة الموافقة بالصعود في الشجرة لرأس الوحدة، يتحقق من التعارض
  والرصيد، يُخطر الموافق التالي، يعيد فحص الرصيد عند الاعتماد النهائي.
- `LeaveDashboardService.RemainingForTypeAsync`: الرصيد = الاستحقاق − المعتمَد هذا العام (محسوب لحظيًا).
- شاشات People/Dashboard + People/Leaves (سلسلة موافقات + تقويم).

### 1.3 الرواتب + جسر المحاسبة ✔ (شغّال ومُختبَر)
- `AccountingPostingService.PreviewPayrollAsync` (BL/AccountingPostingService.cs:55): يحسب لكل موظف نشط:
  `الإجمالي = الأساسي + بدلات` ، تأمينات (موظف/شركة) % ، ضريبة % (لو `IsTaxApplicable`) ، `الصافي = الإجمالي − تأمين الموظف − ضريبة`،
  مع **حلّ مركز التكلفة** بالصعود في الهيكل.
- `SalaryPolicies` — مكوّنات: أساسي/سكن/انتقال/أخرى، نِسَب التأمين، الضريبة، (والإضافي/التأخير/الغياب **معرّفة وغير محتسبة**).
- `PostPayrollRunAsync` (سطر 125) + كيان `PostingRule` (SourceType/ComponentCode/Debit/Credit/CostCenterSource):
  قيد شهري متوازن — مدين مصروف الرواتب 520101 (بمركز التكلفة) ومصروف التأمين 520102، دائن رواتب مستحقة 2103
  وضريبة 210203 وتأمينات 210204 — عبر `JournalEntryService.CreateAndPostAsync` (فحص التوازن/الفترة).
- مُختبَر: `seed-acc-demo` يرحّل 6 أشهر رواتب بنجاح. API: `/api/acc/payroll/preview|post`. شاشة Accounting/Payroll.

## 2) الناقص الحقيقي (بالأولوية والتكامل)

### 2.1 جدول الإجازات الرسمية (Official Holidays) — ✘ 🔴
لا يوجد أي كيان `Holiday/OfficialHoliday`. **الأثر:** حساب أيام الإجازة وأيام العمل/الغياب غير دقيق
(العطلة الرسمية تُخصم خطأً من رصيد الإجازة، والغياب يُحتسب على يوم عطلة). **بسيط ومنفصل وبلوكر** لأي
حساب زمن صحيح. التكامل: يُستهلك من منطق الإجازات الحالي ومن الحضور القادم وحساب الراتب.

### 2.2 التقاط الحضور والانصراف (Attendance) — ✘ 🔴
موجود فقط `AttendancePolicies` (قواعد: وقت الدوام، سماحية التأخير، أيام العمل الأسبوعية، الأذونات)
لكن **لا كيان لتسجيل حضور فعلي** (لا `Attendance/TimeSheet/Shift/CheckIn`). **الأثر:** الإضافي/التأخير/الغياب
في `SalaryPolicies` لا يمكن احتسابها → الراتب حاليًا أساسي+بدلات فقط. هذا أكبر فجوة وظيفية.
- المطلوب: كيان حضور يومي (دخول/خروج/مصدر: جهاز/موبايل/ويب)، ربط بالورديات والأيام الرسمية،
  حساب تأخير/إضافي/غياب، ثم **تغذيتها للراتب** (المكوّنات جاهزة في SalaryPolicies تنتظر القيم).

### 2.3 مخرجات الراتب — ✘ 🟠
- **قسائم الراتب (Payslips AR/EN):** لا كيان Payslip ولا توليد PDF. (القيد المحاسبي موجود، لكن لا مستند للموظف.)
- **صرف الرواتب (Disbursement):** حساب 2103 (رواتب مستحقة) يتراكم ولا يُصفّى — لا تحويل بنكي/نقدي
  (Dr 2103 / Cr بنك). التكامل: عبر BankService/المدفوعات الموجودة.
- **توريد الاستقطاعات:** 210203 (ضريبة) و210204 (تأمينات) يتراكمان بلا توريد للجهات (Dr الالتزام / Cr بنك)
  ولا نماذج إقرار رسمية.

### 2.4 الإجازات — تكميلات — ✘/◐ 🟡
- **بدل الإجازة النقدي (Encashment):** لا تحويل أيام غير مستخدمة لنقدية ولا قيدها.
- **مخصص الإجازات (Leave Provision):** لا التزام محاسبي للإجازات المستحقة غير المنفذة.
- **ترحيل الرصيد (Carry-Over):** `CarryOverLimit` معرّف بلا منطق تنفيذ سنوي.

### 2.5 ملف الموظف — تكميلات — ✘ 🟠
- **عقود الموظف:** لا كيان `Contract` ولا تاريخ بداية/نهاية/نوع ولا **تنبيه انتهاء** (30/60/90 يوم).
- **خزنة المستندات:** كيان `Attachment` عام موجود (به `EmployeeID`) لكن بلا خدمة/شاشة تصنيف
  (هوية/مؤهل/عقد/تأمين) ولا تنبيه انتهاء.
- **تاريخ وظيفي/راتبي:** لا سجل تغيّر المسمى/الراتب، ولا مسار إنهاء خدمة/تسوية نهائية.

### 2.6 مجالات مؤجّلة مقبولة — ⚪
التوظيف/الـ onboarding (مبني جزئيًا)، تقييم الأداء، التدريب، ESS الكامل (جزء عبر الموبايل).

## 3) سلسلة الاعتماد (ليه الترتيب ده)

```
الإجازات الرسمية (2.1) ──┐
                          ├─► الحضور (2.2) ──► خصومات/إضافي ──► الراتب (مبني، ينتظر القيم)
الورديات/التقويم ────────┘                                         │
                                                                    ├─► قسائم الراتب (2.3)
                                                                    ├─► صرف الراتب + تصفية 2103 (2.3)
                                                                    └─► توريد الضرائب/التأمينات (2.3)
```

طبقة الزمن (2.1 + 2.2) هي المفتاح: من غيرها يبقى الراتب ناقصًا والإجازات غير دقيقة. والمحاسبة
جاهزة لاستقبال كل ده (الجسر شغّال).

## 4) خطة المراحل المقترحة

| مرحلة | المحتوى | الأولوية | يتكامل مع |
|---|---|---|---|
| **HR-1** | جدول الإجازات الرسمية + شاشة إدارة + استبعادها من حساب أيام الإجازة/الغياب | 🔴 رخيص | الإجازات، الحضور، الراتب |
| **HR-2** | الحضور والانصراف: كيان يومي + ورديات + التقاط (ويب/موبايل) + حساب تأخير/إضافي/غياب | 🔴 الأكبر | الأيام الرسمية، الراتب |
| **HR-3** | تغذية الحضور للراتب (تفعيل الإضافي/التأخير/الغياب المعرّفة في SalaryPolicies) + قسائم AR/EN | 🟠 | الرواتب (مبني) |
| **HR-4** | صرف الرواتب (تصفية 2103 عبر البنك) + توريد الضرائب/التأمينات للجهات | 🟠 | BankService، المحاسبة |
| **HR-5** | عقود الموظف + تنبيهات الانتهاء + خزنة مستندات مصنّفة | 🟠 | NotificationService |
| **HR-6** | بدل الإجازة النقدي + مخصص الإجازات + ترحيل الرصيد السنوي | 🟡 | المحاسبة |
| **HR-7** | إنهاء الخدمة + التسوية النهائية + التاريخ الوظيفي/الراتبي | 🟡 | الرواتب، المحاسبة |

**التوصية للبدء:** HR-1 (الإجازات الرسمية) فورًا — بلوكر رخيص ومنفصل — ثم HR-2 (الحضور) باعتباره
أكبر فجوة وظيفية وأساس اكتمال الراتب.

## 5) نقاط تكامل يجب احترامها (مع المبني)

- **الهيكل/الفروع/مراكز التكلفة = `Hierarchicals`** (لا تُنشئ بنية تنظيمية جديدة).
- **الموافقات = نفس نمط `LeaveApprovalStep`/سلسلة الصعود في الشجرة** (لا workflow جديد).
- **أي قيد محاسبي عبر `JournalEntryService` فقط** + `PostingRule` (للحضور/الصرف/التوريد أضِف Rules لا منطق GL مبعثر).
- **الثوابت:** أي مستحقات رواتب/إجازات تتسق مع حساباتها التحكّمية (2103/210203/210204) — يُراقَب بحارس السلامة.
- **AR/EN + Metronic صافي + بحث حقيقي + أشجار collapse/expand** في كل شاشة جديدة.
- **DECIMAL(19,4)**، سكيمة يدوية sqlcmd ([LineNo] بأقواس، NCHAR)، اسم جدول EF = اسم الـ DbSet (جمع).
