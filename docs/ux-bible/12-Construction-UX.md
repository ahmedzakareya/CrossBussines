# 12 — Construction UX

Construction evolves from the implemented `Views/Project` estate and supporting services; dedicated construction workspaces may be planned or architecture-only. Never label them implemented solely from roadmap intent.

The experience centers on project/site context, contract, budget, schedule, quantities, change, document, responsibility and approval state. Portfolio uses dashboard/collection patterns; project home uses a contextual workspace; record pages use summary + tabs/timeline; field execution uses touch-first capture with sync status.

Permissions combine company, project, contract, role and commercial sensitivity. States include draft/submitted/approved/rejected, superseded revision, offline/pending sync, conflict, unavailable integration, denied commercial data, and success with audit reference. Field errors preserve captured data. Photos/files disclose upload progress and retry.

Mobile orders safety/task/context before commercial detail; tablet supports split list/detail; desktop supports comparative tables. RTL uses logical layout and preserves document/reference codes. Keyboard and accessible file alternatives are required. Cache bounded field data and avoid assuming connectivity. Future dedicated screens must start compliant with `38-Screen-Blueprints.md` and reuse Projects, Tasks, Calendar, Reporting and Communication rather than duplicate them.
