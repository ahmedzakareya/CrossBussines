# 16 — AI UX

AI is an assistive capability, not an authority or a substitute navigation system. Current repository evidence does not establish a complete activated AI product; treat proposed surfaces as planned until implementation and verification exist.

Every AI surface identifies that content is generated, shows its business/context scope, cites or links retrievable sources where possible, and requires user review before consequential action. Never silently post, approve, pay, delete, message, or change records. Permissions and company isolation are applied before retrieval and again before action.

States: preparing context, generating with cancel, partial stream, insufficient evidence, unavailable model, denied source, policy refusal, recoverable error, completed draft, accepted/edit/rejected feedback. Preserve the user's input on failure. Avoid anthropomorphic certainty; express limitations and freshness.

Keyboard and screen readers receive status without excessive announcements; reduced motion disables ornamental streaming effects. Mobile uses a drawer/full-screen assistant without obscuring critical context. Performance budgets cap context and show long-running work. Future evolution must pass Security, Privacy, domain-owner and UX governance review.
