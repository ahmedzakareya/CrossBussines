The binding constraint is not feature scope. It is integration, and it is now the first executable phase.

## 4. Findings that shaped the plan

**1 · The deployment split is real, and partly already instrumented.** Two roots — 57 and 60 slices — with 4 filenames in both and **none byte-identical**. But `CrossBuy/deploy/sql/manifest.json`, generated by `scan-sql-manifest.ps1`, **already registers all 115 scripts** with SHA-256, apply rank and an idempotency verdict, and already flags those 4 as ambiguous. *This corrects the previous assessment*: the **authored** side is instrumented; the **applied** side is not, because `platform_schema_history.sql` has never been applied. Governance therefore extends the manifest rather than replacing it — building a parallel registry would recreate the very defect the two trees demonstrate.

Two further facts emerged: **`hm16_rename_grni.sql` is classified `review`** — an unguarded, unread, mutating script in the tree — and **`deploy/README.md` states provisioning is actually BACKUP/RESTORE of `CrossBuyDB2`**, not script replay, because EF migrations are broken and ~90 ad-hoc scripts in `C:/temp` built the schema. That is a third source of truth outside the repository.

**2 · Three platforms reach zero users.** Reporting 221/221, Communication 274/274, Construction C1 38/38 — **533 tests, 34 tables, 0 screens**. Construction is sharpest: services registered in `Program.cs` against tables that exist in no database.

**3 · Tasks and Calendar are not greenfield.** Tasks has a controller, 5 views, an access service, 7 SQL slices and **two registered hosted services**. Calendar has a service, controller and slice. Both are now owned by decision (D-32, D-33) and their work is **integration and remediation, not new construction**.

**4 · "Communication" names two things.** The Communication *Platform* is unactivated with no UI. The *legacy* `BL/Comm` module **is** active with a registered dispatcher and 3 views. Their status is never merged.

## 6. The Workspace constraint that matters most

> **The Workspace adds NO permissions of its own.** Every read delegates to the owning module's access service.

Recorded as **RSK-23**: a unified cross-module surface is exactly where an authorization shortcut gets introduced — one efficient joined query returning what the user could not see module by module. The platform already knows that *hiding a control is not a control*; the inverse holds too — **showing an aggregated row is an authorization decision**, and the module that owns the row must make it. R3 carries per-module delegation tests as a gate.

## 7. Execution model

**Per-tab git worktrees plus a protected integration branch**, governed by a 12-point gate.

> **No tab may leave the shared integration branch unbuildable.**

A breaking merge is reverted, not fixed forward — fixing forward blocks the other three tabs for the duration. Registers delivered: Tab Ownership (including **Tasks/Calendar as UNASSIGNED** and the Integration Owner as **to be appointed**), Shared Files (13, including `crossbuy-brand.css` frozen), ADRs (44, with ADR-038–044 reserved), SQL Slices (22).
