  3. صقل الشاشة: حقول العملة + العميل، و**نسخ قائمة (Copy)**.

## 2) النموذج المستهدف — أبعاد التسعير
السعر يُختار حسب: **الصنف** + (**عميل بعينه** أو **شريحة** أو عام) + **كسر الكمية** + **فترة السريان** + **العملة**.

### 2.1 العملة (المبدأ المحوري)
- كل قائمة أسعار لها **عملة واحدة** (`CurrencyId`؛ null = عملة الفرع الوظيفية).
- **السعر الأجنبي مثبّت** يُكتب مباشرةً في البند (لا يُحسب من الجنيه × الصرف) — التزامًا بالمواصفة 2.2.
- عند تسعير مستند بعملة C: **تُرشَّح القوائم بعملة C فقط** (أو القوائم بعملة الفرع لو C = عملة الفرع). فلا تُخلط أسعار عملات.
- العملة في المستند تُورَّث من الفرع وتُتجاوز بصلاحية `currency-override` (مبنية في الموديول 1) — ولا تحتاج تجاوزًا منفصلًا في التسعير؛ عملة المستند هي التي تحدّد القوائم المؤهّلة.

### 2.2 العميل بعينه + الشريحة + العام (الأولوية)
أولوية الأخصّ يكسب الأعمّ:
1. **قائمة لعميل بعينه** (`CustomerId == العميل`).
2. **قائمة لشريحته** (`CustomerId == null && Segment == شريحة العميل`).
3. **قائمة عامة** (`CustomerId == null && Segment == null`).
ثم داخل نفس المستوى: `Priority` الأعلى، ثم أعلى `MinQty` مؤهّل (كسر الكمية الأدق).

### 2.3 كسر الكمية + الصلاحية
✅ موجودان ويعملان — يُبقيان كما هما.

## 4) إعادة تصميم محرّك الاختيار (`GetPriceAsync`)
التوقيع الجديد:
```
GetPriceAsync(companyId, itemId, customerId?, segment?, currencyId?, qty, asOf) → PriceResult{ UnitPrice, DiscountPercent, CurrencyId, PriceListId, Source }
```
الخوارزمية:
1. رشِّح بنود القوائم: `IsActive` + `ItemId` + `MinQty<=qty` + صلاحية القائمة والبند ضمن `asOf` + **مطابقة العملة** (`pl.CurrencyId == currencyId` أو كلاهما null/عملة الفرع) + **مطابقة الاستهداف** (`pl.CustomerId==customerId` أو `pl.CustomerId==null && (pl.Segment==null || pl.Segment==segment)`).
2. رتّب: **عميل-محدّد** > **شريحة-محددة** > عام، ثم `Priority`، ثم أعلى `MinQty`.
3. **تدرّج النتيجة (fallback متدرّج — محسوم):**
   - **(1) قائمة بعملة المستند** (الأخصّ يكسب: عميل > شريحة > عام) → سعر **مثبّت**، `Source="list"`.
   - **(2) لا قائمة بالعملة:** إن كان إعداد الأدمن `ConvertBasePriceForForeignDocs` مفعّلًا و`Item.SalesPrice` موجود → سعر **محوّل مؤقت** = `SalesPrice × سعر اليوم (Sell)`، `Source="converted"` ومعلَّم بوضوح كـ«سعر محوّل/مؤقت» مع تنبيه، **قابل للتعديل** (ليس مثبّتًا). إن كان الإعداد مُطفأ → يُتخطّى لـ(3).
   - **(3) لا قائمة ولا سعر أساسي (أو الإعداد مُطفأ):** السعر = 0، `Source="none"`، تنبيه + **إدخال يدوي إلزامي**.
   - ملاحظة: لمستند بعملة الفرع (EGP) يبقى السلوك كما اليوم: قائمة EGP ثم `Item.SalesPrice` بسعر 1 (`Source="base"`).
4. `PriceResult` يرجع `CurrencyId` + `Source` (`list`/`converted`/`base`/`none`) ليُظهر JS التنبيه/الشارة المناسبة عند `converted`/`none`.

التكامل: `PriceLookup` و JS في أوامر البيع/عروض الأسعار يمرّران **عملة المستند** (المختارة في الموديول 1) + العميل. السعر المُرجَع يُملأ في السطر بعملة المستند مباشرةً.

## 5) الشاشة المستقلة (صقل)
- **محرّر القائمة:** + منسدلة **العملة** (افتراضي عملة الفرع) + منتقي **العميل** (اختياري؛ فارغ = شريحة/عام) + الإبقاء على الشريحة/الأولوية/الصلاحية/الافتراضي.
- **شاشة القائمة:** أعمدة العملة + العميل/الشريحة + فلاتر، وزر **نسخ قائمة (Copy)** ينسخ القائمة وبنودها كمسودة جديدة.
- (اختياري لاحق) أداة تعديل نسبي جماعي للأسعار، واستيراد بنود من Excel.
- تبقى **مستقلة تمامًا** (ليست داخل شاشة الصنف) — كما هي الآن.

## 7) القرارات — **محسومة** ✅
1. **غياب قائمة بالعملة:** ✅ **تدرّج قابل للضبط** (§4-3): قائمة بالعملة → سعر محوّل مؤقت معلَّم (إن كان الإعداد مفعّلًا) → 0 + إدخال يدوي. يُضاف إعداد أدمن `ConvertBasePriceForForeignDocs` (مع توضيح) — **الافتراضي: مفعّل** (يعرض سعرًا محوّلًا مؤقتًا للراحة، معلَّمًا بوضوح؛ يمكن إطفاؤه لفرض الإدخال اليدوي وفق مبدأ السعر المثبّت).
2. **قوائم العميل بعينه:** ✅ إضافة `PriceList.CustomerId` والأولوية **عميل > شريحة > عام**.
3. **خلط العملات:** ✅ **لا** — القوائم لا تُحوَّل أبدًا (كل قائمة بعملتها)؛ التحويل المؤقت في (2) يخصّ `Item.SalesPrice` فقط (سعر أساسي، لا قائمة) ومعلَّم كمؤقت.

**إعداد جديد:** `InventorySettings.ConvertBasePriceForForeignDocs bool` (افتراضي true) — يُعرض في إعدادات المخزون/التسعير مع شرح أثره.
