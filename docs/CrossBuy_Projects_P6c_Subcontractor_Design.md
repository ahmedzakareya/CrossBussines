# CrossBuy — المشاريع والمقاولات — P6-ج: مستخلص الباطن / المعدات — تصميم فقط

> **الحالة:** تصميم بانتظار مراجعتك. **لا كود بعد.** يمسّ المدفوعات (AP). يُبنى فوق: `PayableService` (الموردون + فواتير الشراء + المدفوعات) + الباطن كمورّد + بُعد `ProjectId` + حساب التكلفة 510104 (P5) + نمط مستخلص العميل (P4).

---

## 1. النطاق والمبادئ
- **الهدف:** تسجيل تكلفة **مقاولي الباطن / إيجار المعدات** الفعلية على المشروع (موسومة `ProjectId`) فتُكمل الربحية = الإيراد − (مواد + عمالة + **باطن**).
- **أي قيمة مالية عبر الخدمات القائمة فقط:** الدائنون/الفواتير عبر `PayableService`؛ القيود عبر `JournalEntryService`. **لا كاتب جديد.**
- **`ap_sub` سليم:** حساب الدائنين لا يُمسّ إلا عبر مستند (فاتورة شراء / دفعة / مرتجع) — لا قيد خام (نفس مبدأ ar_sub في P4).
- **`inv-test-integrity = 0`** (بالأخص `ap_sub` + `tb_balanced`).

---

## 2. ⚠️ القيد المركّب (آمن للدفتر المساعد AP) — تحققتُ من الكود

**الحقيقة (من `IntegrityCheckService`):** `apGl = −GlNet(حسابات الموردين)` ويجب أن يساوي `apSub = Σ فواتير شراء − Σ مدفوعات − Σ مرتجعات شراء`. فأي تخفيض لحساب الدائنين يجب أن يمرّ عبر **دفعة** أو **مرتجع** (مستند)، لا قيد خام.

**مثال:** عمل باطن الفترة W=50,000 · ض.ق.م مدخلات 14% T=7,000 · محتجز باطن 10% R=5,000.

| # | عبر الخدمة | المستند | القيد | مساعد |
|---|---|---|---|---|
| 1 | `CreatePurchaseInvoiceAsync` (سطر خدمة: ExpenseAccountId=**510104**, projectId) | فاتورة باطن W+T | Dr **510104** 50,000 [ProjectId] · Dr **110401** ض.ق.م مدخلات 7,000 / Cr **الدائنون** 57,000 | فاتورة +57,000 |
| 2 | `CreatePaymentAsync` (cashAccountId=**2105**) | دفعة «محتجز» | Dr **الدائنون** 5,000 / Cr **2105** محتجزات الباطن 5,000 [ProjectId] | دفعة +5,000 |

**الأثر المجمّع (متوازن):**
```
Dr 510104 تكلفة المشروع    50,000 [ProjectId]
Dr 110401 ض.ق.م مدخلات      7,000
      Cr الدائنون (صافي)          52,000   (= 57,000 − 5,000)
      Cr 2105 محتجزات الباطن       5,000 [ProjectId]
                            ───────   ───────
                            57,000    57,000  ✔
```
**التحقق المساعد:** apSub = 57,000 (فاتورة) − 5,000 (دفعة) = **52,000** = رصيد الدائنين للمورّد. ✔ ap_sub سليم.
> نموذج P4 نفسه معكوسًا على جانب الدائنين: المحتجز = «دفعة» وجهتها حساب الالتزام 2105 بدل النقدية (تمامًا كما كان محتجز العميل «قبضًا» وجهته 1104). إن كانت نسبة المحتجز 0 → السطر (2) يُلغى، وتبقى الفاتورة فقط.

### نقطة الحسم التقنية الوحيدة (بـ ProjectId)
`CreatePaymentAsync` هي الخدمة القائمة الوحيدة التي **تنقصها** `projectId` (شقيقتها `CreatePurchaseInvoiceAsync` تملكه). لوسم رجل 2105 بالمشروع (وقراءة رصيد محتجز الباطن للمشروع من الـGL): **توسيع `CreatePaymentAsync` بـ `int? projectId = null`** — نفس نمط توسيع `CreateReceiptAsync` في P4 (اختياري، بلا تغيير سلوك عند null، ليس كاتبًا جديدًا). **موصى به.**

## 3. نقاط الحسم (خيارات + توصية)

### 3-1 مقاول الباطن = مورّد؟
**✅ التوصية: مورّد (Vendor) قائم — إعادة استخدام.** لا كيان طرف جديد؛ الباطن/مورّد المعدات = Vendor له ControlAccountId (2101). (اختياري: حقل `IsSubcontractor` على Vendor للتصفية — أو نتركه بلا تمييز.)

### 3-2 عقد الباطن
**✅ التوصية: كيان `Subcontract` خفيف** (ProjectId + VendorId + Value + RetentionPercent + Status) — لأن المشروع الواحد له **عدة** مقاولي باطن (فلا يمكن وضع النسبة على Project كما في P4). المستخلصات تُبنى تحته وتُراكم لكل عقد باطن.

### 3-3 المعالجة المحاسبية (القسم 2 أعلاه)
**✅ التوصية:** فاتورة شراء (W+T، سطر خدمة إلى 510104، projectId) + المحتجز كـ**دفعة تسوية** وجهتها **2105** (حساب التزام جديد «محتجزات مقاولي الباطن»، مثل 1104 لكن دائن) — عبر `PayableService`، ap_sub سليم. يتطلب توسيع `CreatePaymentAsync` بـ projectId (حسم 2 أعلاه).

### 3-4 المعدات
**✅ التوصية:** **إيجار المعدات = فاتورة مورّد بنفس الآلية** (مورّد = مؤجّر المعدات، سطر خدمة إلى 510104). **إهلاك المعدات المملوكة وتحميله للمشروع = مؤجّل** (بند مستقل، عبر الأصول الثابتة). فـP6-ج = الباطن + إيجار المعدات (كلاهما فاتورة خدمة مورّد).

### 3-5 الحالة + منع الازدواج
**✅ التوصية: مسودة/معتمد/مرحّل** (نمط مستخلص العميل P4). قيمة الفترة = التراكمي − المفوتر سابقًا لعقد الباطن (لا ازدواج). المرحّل لا يُرحّل ثانيةً؛ الترحيل عند الاعتماد.

### 3-6 رد محتجز الباطن (لاحقًا)
**✅ التوصية: تأجيل إلى P6-ج-2** — عند تسليم الباطن: **Dr 2105 / Cr نقدية** موسوم ProjectId (قيد مباشر، لا يمسّ الدائنين فآمن — مرآة P6-ب). P6-ج الآن = الفوترة + الحجز فقط.

## 4. نموذج البيانات (إضافي، لا يمسّ الموجود)
- حساب **2105 «محتجزات مقاولي الباطن»** (LIABILITY، postable، تحت 21) — جديد مثل 2104/1104.
- **`Subcontract`** (رأس): ID, CompanyID, ProjectId, VendorId, ContractValue, RetentionPercent, Status, CreatedAt.
- **`SubcontractBilling`** (مستخلص الباطن): ID, SubcontractId, ProjectId, BillingNo, Date, Status(Draft/Approved/Posted), GrossWork(W), TaxRate/TaxAmount(T), RetentionPercent/Amount(R), NetPayable(=W+T−R), PurchaseInvoiceId?, RetentionPaymentId?, + سطور اختيارية (وصف/قيمة الفترة). SQL: `deploy/sql/projects_p6c_subcontract.sql`.

## 5. الخدمة `ISubcontractBillingService`
- `BuildPreview` (قيمة الفترة = تراكمي − مفوتر سابقًا؛ W/T/R/net). `SaveDraft` / `Approve` / **`Post`** (فاتورة شراء عبر `CreatePurchaseInvoiceAsync` + دفعة محتجز عبر `CreatePaymentAsync(cashAcc=2105, projectId)` إن R>0) / (لاحقًا) `ReleaseRetention`. حرّاس الازدواج. الأرصدة من الـGL.

## 6. الشاشة (بانتظار تصميمك — لا أجتهد)
نقطة الدخول: زر «الباطن» على صف المشروع (أو ضمن شاشة المشروع). قائمة عقود الباطن + مستخلصاتها، والمحرّر بنمط **مستخلص العميل P4** (اختيار عقد الباطن + قيمة الفترة + الضريبة + المحتجز → **كشف**: W → +ضريبة → −محتجز → = صافي المستحق للمورّد) + أزرار حفظ/اعتماد/ترحيل.
**سؤالي:** أطبّق **توسيع `CreatePaymentAsync` بـ projectId + حساب 2105**؟ وأي نمط للشاشة (قائمة + محرّر بنفس الصفحة كـP4؟) — أم نمط فاتورة/دفعة الحسابات؟
