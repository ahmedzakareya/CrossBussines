# CrossBuy — POS-B (Table Reservations) Design & Build

**Status:** design approved 2026-07-08. Builds on `RestaurantTable` + `Customer` (POS-4e) + the derived table status + the unified Restaurant system (POS-A). OPERATIONAL only — ZERO accounting effect (no invoice/discount/GL); the invoice comes at payment like any order. inv-test-integrity=2. Offline-ready.

## Approved decisions
1. **Floor status = 3-way DERIVED (no manual field):** Occupied (has an open order) > Reserved (a Booked reservation for today within a lead window) > Available. A reserved table shows a distinct badge/colour + time + guest; it becomes Occupied when an order opens on it (arrival) — POS-B2.
2. **Overlap prevented by window:** each reservation has `DurationMinutes` (default 120). A new Booked reservation whose `[start, start+duration)` intersects an existing Booked one on the same table is rejected. Cancelled/NoShow ignored.
3. **One table per reservation (v1)** — multi-table deferred.
4. **Guest = `GuestName`+`GuestPhone` (required) + optional `CustomerId` link** (delivery-address pattern).
5. **Status:** Booked → Arrived / Cancelled / NoShow. Arrival opens a Dine-in order (POS-B2).
